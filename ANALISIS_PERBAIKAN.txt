   Solusi: Payment-Deferred Stock Decrement Pattern
   
   ✅ SEBELUM (❌ Tidak Aman):

      2. Create order (status='pending_payment', stok AMAN)
      3. Redirect ke payment page
      4. Payment confirmed → confirmPayment() (stok dikurangi, status='paid')
      5. Jika payment gagal → order tetap 'pending_payment', stok AMAN
   
   Implementasi:
   
   ✅ CartController.processCheckout() - MODIFIED:
      - NOT decrement stock anymore
      - Set status to 'pending_payment'
      - Keep validation & transaction
      - Stok akan dikurangi di confirmPayment()
   
   ✅ Order Model - NEW METHODS:
      - confirmPayment(): Validate + Update status + Decrement stok (atomic)
      - cancelOrder(): Cancel pending orders (stok tidak berubah)
      - isPaid(), isPendingPayment(), isCancelled(): Status helpers
   
   ✅ OrderController - NEW METHODS:
      - confirmPayment($id): Call Order::confirmPayment() after payment
      - cancelOrder($id): Allow cancelling pending payments
   
   ✅ Routes - NEW ENDPOINTS:
      - POST /history/{id}/confirm-payment (protected)
      - POST /history/{id}/cancel (protected)
   
   Security & Business Benefits:
   ✅ Prevent overselling (stok hanya berkurang saat payment confirmed)
   ✅ Atomic transactions (all or nothing)
   ✅ No financial loss (payment fail = stok aman)
   ✅ User authorization (only their own orders)
   ✅ Clear workflow (pending_payment → paid or cancelled)
   ✅ Payment gateway ready (just call confirmPayment())
